# Эксплуатация

## PostgreSQL + Supabase

1. Создайте собственный Supabase-проект. Скопируйте `.env.example` в `.env.local`; задайте `DATABASE_URL`, `AUTH_PROVIDER=supabase`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `STORAGE_PROVIDER=supabase`, `DEMO_SEED=false`, HTTPS `APP_ORIGIN` и случайный `CRON_SECRET`.
2. Для PostgreSQL используйте прямое соединение или session pooler с SSL. Выполните `npm run db:migrate` на пустой базе. Эта команда создаст таблицы, оператора и роли без демонстрационных аккаунтов.
3. Примените `supabase/002_postgis_rls.sql` через SQL Editor Supabase. Он добавляет географическое поле PostGIS и GiST-индекс, включает RLS на всех бизнес-таблицах и закрывает прямой доступ anon/authenticated. Браузер работает через Next.js API. Для серверного соединения необходима доверенная роль с доступом к этим таблицам.
4. Создайте первого пользователя с паролем в Supabase Auth Dashboard. Затем выполните `npx tsx scripts/provision-user.ts admin@example.com "Имя администратора" admin`. Скрипт не отправляет писем и не создаёт внешние аккаунты: он связывает уже существующий Auth UUID с профилем оператора.
5. Запустите приложение, войдите и настройте организации, типы конструкций/документов, районы, шаблоны и сотрудников. Дополнительные Supabase-профили подключайте тем же скриптом; роли и деактивация доступны администратору внутри приложения.
6. Разверните Next.js на постоянном Node.js-хосте за HTTPS-прокси. Текущий npm start намеренно слушает только localhost; для обратного прокси на том же сервере этого достаточно. На контейнерном хосте используйте `node node_modules/next/dist/bin/next start --hostname 0.0.0.0 --port 3000` и закрытый сетевой периметр.
7. Настройте серверный планировщик: `POST /api/cron`, заголовок `Authorization: Bearer <CRON_SECRET>`, раз в минуту. Не публикуйте секрет в URL. Повторные вызовы безопасны.

Облачные адаптеры и миграция включены в репозиторий, но не проверены на живом Supabase-проекте без ключей владельца. Перед промышленным использованием выполните приёмочные проверки, отдельный аудит доступа, нагрузочные проверки и пробное восстановление резервной копии.

## Карта

По умолчанию загружаются тайлы OpenStreetMap с обязательной атрибуцией. Для промышленной нагрузки выберите подходящего поставщика и укажите `NEXT_PUBLIC_TILE_URL` и `NEXT_PUBLIC_TILE_ATTRIBUTION` **до сборки**, затем пересоберите приложение. Браузер обращается к поставщику напрямую. Геокодирование не подключено: адрес вводится вручную, координаты можно выбрать на карте. При недоступных тайлах реестр и карточки остаются доступны.

## Резервная копия локального режима

1. Остановите приложение (`Stop-AdAsset.ps1`; для dev — Ctrl+C в его терминале).
2. Выполните `npm run backup`. Получится `backups/<UTC timestamp>/` с `postgres/`, `files/` и `manifest.json`. Скрипт отказывается копировать открытую базу.
3. Отдельно сохраните `.env.local` в защищённое место. Не кладите его в GitHub. Копия БД содержит сессии и хеши локальных паролей: ограничьте доступ и используйте шифрование диска/архива.
4. Скопируйте резервную копию на отдельный носитель. На исходном ноутбуке можно настроить Windows Task Scheduler для запуска резервирования после корректной остановки приложения.

## Восстановление локального режима

1. Остановите приложение и сохраните текущую `.data` под **новым** именем, не удаляя её.
2. Создайте новую пустую `.data`; скопируйте в неё каталоги `postgres` и `files` из одной согласованной копии. Не копируйте старый `database.pid`.
3. Восстановите `.env.local` с теми же настройками провайдеров и совместимую версию исходников/зависимостей из Git.
4. Запустите приложение. Проверьте вход, количество объектов, один приватный документ, фотографию и историю. Откройте карточку с несколькими дефектами и убедитесь, что состояния сохранены.
5. Перед возвратом в эксплуатацию отзовите прежние сессии командой `DELETE FROM sessions;` через доверенный администраторский доступ к **восстановленной** базе при остановленном приложении.

## Резервирование PostgreSQL/Supabase

`npm run backup` при наличии `DATABASE_URL` вызывает `pg_dump --format=custom`. PostgreSQL client tools должны быть установлены отдельно; пароль передаётся только через переменную среды дочернего процесса. Для восстановления используйте `pg_restore` в **новую** базу и проверьте миграции/права. Не выполняйте пробное восстановление поверх рабочей БД.

При Supabase Storage резервная копия PostgreSQL **не содержит** файлы бакета. Настройте отдельное копирование объектов Storage или резервирование провайдера. В `manifest.json` указан провайдер хранения, чтобы это ограничение было видно. Для production используйте управляемые ежедневные бэкапы/PITR и регулярно проверяйте восстановление.

## Диагностика

- Локальные логи фонового запуска: `.local/server.out.log`, `.local/server.err.log`.
- Нет доступа к файлу: проверьте вход, операторскую принадлежность и наличие файла в хранилище; обновите ссылку после истечения 60 секунд.
- Конфликт версии: обновите карточку, сравните актуальные данные, повторите изменение с новой версией. Не меняйте version вручную для обхода проверки.
- Не видны черновики в реестре: откройте расширенные фильтры и включите «Показать черновики и карточки на проверке».
- Не работает камера: требуется HTTPS или localhost и разрешение браузера; доступен ручной ввод URL/ID из QR.
- Нет email: в этой версии почтовый сервис не подключён, доступны внутренние уведомления.
